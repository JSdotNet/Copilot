When creating or editing customization assets, enforce naming and frontmatter rules: agent files as role.agent.md with name and description, skill files as SKILL.md with name and description, plugin contracts as resources/<name>.md with name and description and never applyTo, repository rules as .agents/rules/<topic>.md with name, description, and paths plus one wrapper per host, and plugin manifests with valid component path mappings. These assets load in both GitHub Copilot and Claude Code from a single copy, so also enforce the dual-host rules: never pin a model in an agent (record the preference in a ## Model body section instead, because Claude refuses to load an agent whose model id it does not recognise); author agent tools as one union list of Copilot ids followed by the Claude names tools/tool-map.json derives from them, granting an MCP server in both the plugin-namespaced and the bare spelling; never give a non-runner agent a session-spawning or delegation tool; document every handoff target in the agent body because Claude ignores the handoffs key; reference every contract explicitly by path because neither host auto-applies a file from inside a plugin; keep host-specific tool names out of skill prose; and author hooks as type: prompt, except sessionStart, which is dead on arrival in Claude Code and needs a hand-authored twin in hooks/: a command hook printing hooks/session-start-context.md, which holds the same text. Nothing is generated: both manifests (.github/plugin/plugin.json and .claude-plugin/plugin.json), the marketplace entry, and both hook files are hand-authored, so a change to one side is a change owed to the other, and node tools/check-assets.mjs must pass before committing. Full rules: docs/copilot/claude-code-compatibility.md and plugins/spec-builder/resources/create-instruction.md. Keep every authored asset concise: state each rule in exactly one file and point at it by relative path from everywhere else, delete any sentence that does not change behavior versus the model default, and stay inside the body budgets (SKILL.md 40 lines, resources contracts and rules 60, *.agent.md 80) or state why the asset exceeds one. Full rules: plugins/spec-builder/resources/spec-conciseness.md.
