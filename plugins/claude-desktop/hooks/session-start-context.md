The claude-desktop plugin is loaded. It provides the orch-dashboard MCP server (a run dashboard, Mermaid diagram viewer, and Markdown document viewer) and three skills: start (bring the repository's application up and open it), session-handoff (package this session's state into a brief another session continues from), and create-pull-request (open a pull request for the current branch). Address the dashboard tools by the name the host actually exposes -- a plugin-provided MCP server is namespaced with the plugin, so they surface as mcp__plugin_claude-desktop_orch-dashboard__* when installed as a plugin, and as mcp__orch-dashboard__* when the server is registered directly in a repo's .mcp.json; resolve the prefix from the available tool list rather than assuming one, and never block work on failing to open the dashboard. The plugin's telemetry hook raises context-gauge warnings at 60%, 75%, and 85%: at 75% persist decisions and start nothing heavy, at 85% run session-handoff. Staged delivery flows (flow-*), shared phases, the pull-request lane beyond create-pull-request, scheduled entries, and cross-session fan-out are not this plugin's: they ship as delivery, delivery-schedule, and fleet in the jsdotnet marketplace (JSdotNet/ai-agent-stack). A repo may declare its runtime context in .claude/orch-context.md and its developer start in .claude/start.md; neither sets a model or holds a secret. The repo's own .mcp.json and instructions remain the source of truth for MCP servers.
